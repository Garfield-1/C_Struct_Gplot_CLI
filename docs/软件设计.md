# 软件设计

## 概述

`C Struct Gplot CLI`项目是一个纯`python3`代码开发实现的`C`语言静态分析器

项目最初是为了写博客时不用再繁琐的手绘结构关系，目标是要做成可导入项目代码然后生成图像，并且可以编辑保存图像元素的`GUI`版本，中途考虑功能划分和`CLI`使用的场景，独立拆分出了这个项目

本文旨在介绍`C Struct Gplot CLI`项目的整体设计思路和关键对外接口，以便后来者理解和二次开发

## 整体流程

1. 导入项目代码
2. 对压缩包的解压缩、目录的递归扫描
3. 对`C`文件和`H`文件的预处理，这一步类似编译器的预处理，但是并不会展开宏
4. 静态扫描预处理后的文件，提取`struct\union\enum`的定义代码
5. 将提取的结果保存在`DB`文件中
6. 生成`DB`中的`ui_json`字段供后续`ui`生成使用
7. `ui`生成

## 数据库设计

数据库包含两张表

**structures表**

```python
TABLE_NAME = "structures"

TABLE_COLUMNS = {
    'id': 'INTEGER PRIMARY KEY AUTOINCREMENT',
    'salt': 'TEXT',
    'hash': 'TEXT',
    'data_type_latter': 'TEXT NOT NULL',
    'data_type_first': 'TEXT NOT NULL',
    'typedef_names': 'TEXT',
    'content': 'TEXT',
    'ui_json': 'TEXT',
    'source_file': 'TEXT',
    'parent_num': 'INTEGER DEFAULT 0',
    'child_num': 'INTEGER DEFAULT 0',
}
```

**字段具体含义**

| 字段名             | 含义                                                         |
| ------------------ | ------------------------------------------------------------ |
| `id`               | 自增`id`，无特殊含义                                         |
| `salt`             | 盐值，随机生成的十六位长度字符串，用于`hash`计算             |
| `hash`             | 哈希值，用于唯一的标记某个结构，计算方法是对`content+salt`拼接的字符串计算`md5` |
| `data_type_first`  | 复合类型结构的前半部分，例如`struct mesh_leaf`的`data_type_first`是`struct` |
| `data_type_latter` | 复合类型结构的后半部分，例如`struct mesh_leaf`的`data_type_latter`是`mesh_leaf` |
| `typedef_names`    | `typedef`关键字重命名的名字                                  |
| `content`          | 结构体定义的原始字符串，这里只包含`{}`和`{}`之间的内容       |
| `ui_json`          | 用于`ui`显示时读取的`json`字符串                             |
| `source_file`      | 当前结构所在的文件                                           |
| `parent_num`       | 父节点数量                                                   |
| `child_num`        | 子节点数量                                                   |

**relations表**

```python
TABLE_NAME = "relations"

TABLE_COLUMNS = {
    'id': 'INTEGER PRIMARY KEY AUTOINCREMENT',
    'parent': 'TEXT NOT NULL',
    'child': 'TEXT NOT NULL',
}
```

**字段具体含义**

| 字段名   | 含义                                                         |
| -------- | ------------------------------------------------------------ |
| `id`     | 自增`id`，无特殊含义                                         |
| `parent` | `structures`表中的`hash`字段，是`child`字段的父节点，`structures`表中每个`hash`都在`relations`表中占至少出现一次 |
| `child`  | `structures`表中的`hash`字段，是`parent`字段的子节点         |

## ui_json

`ui`渲染时读取此字段，最小化的包含了`ui`显示的所有必要信息

```json
{
    "table_head": {
        "type": "Type",
        "name": "Name",
        "typedef_name": ["Type Definition Name"],
        "hash": "Hash",
        "parent_hash": ["0x1234567890abcdef","0x1234567890abcdef"]
    },
    "table_body": {
        "members_1": {
            "member_context": "int members_1",
            "child_hash": [null]
        },
        "members_2": {
            "member_context": "class members_2",
            "child_hash": ["0x1234567890abcdef"]
        },
        "members_3": {
            "member_context": "class members_3",
            "child_hash": ["0x1234567890abcdef","0x1234567890abcdef"]
        }
    }
}
```
